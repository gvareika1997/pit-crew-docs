The phases of a run. Each one is a slash command you type in Claude Code. Phase pages: [plan](../../how-it-works/plan/), [dev](../../how-it-works/dev/), [test](../../how-it-works/test/), [deploy](../../how-it-works/deploy/).

## `/pit-crew:plan`

Phase 1. Discusses the request at the business level first and stops at a gate for your approval. It creates the ticket in the tracker, or runs without one. Then it designs the high-level architecture and stops at a second gate. A bug first runs a read-only triage, which `--no-triage` skips. Once you approve the architecture, it chains into implementation and runs unattended to green PRs when the session can write. Otherwise it stops with a relaunch line.

**Arguments:** `[what you want to build — or an existing state.json path to resume] [--auto] [--no-triage] [--tracker <provider>] [--audience dev|product]`

## `/pit-crew:dev`

Phase 2. Implements the approved work, runs the affected tests, reviews by risk and checks the acceptance criteria. Then it continues into the test phase.

**Arguments:** `[path to state.json — defaults to the most recent one]`

## `/pit-crew:test`

Phase 3. Runs the test scope the change earned, opens the PRs, verifies the relevant behavior in DEV, resolves actionable feedback, reports the results and cleans up.

**Arguments:** `[path to state.json — defaults to the most recent one]`

## `/pit-crew:deploy`

Phase 4. Manual only, never chained from another phase. Merges the run's approved PRs one at a time and drives each service's production rollout to completion: busy check, freeze check, version confirmation, a canary loop that advances on clean observed signals, and rollback detection. With `--driver human` you merge and advance each step while it monitors and recommends.

**Arguments:** `[path to state.json] [--driver human|agent]`

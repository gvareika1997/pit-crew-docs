A skill is a set of instructions Claude Code loads for one kind of task. You rarely name one: the phase commands load the skills they need.

## Skills you type

These run only when you type them. The model never loads them on its own.

| Skill | What it does |
|---|---|
| `/pit-crew:brainstorm` | Takes an idea too big for one ticket to a decided initiative: a focus statement, research, alternatives, one chosen option, a shareable page and, after you approve it, one tracker project with a milestone per deliverable. |
| `/pit-crew:bro` | Restates the last message in plain language, with no jargon. |
| `/pit-crew:setup` | First-time setup and health check: inventories what Pit Crew needs, proposes a cleanup with a backup and a restore, and guides the credentials and connectors of the roles that are on. |

## Skills that load on their own

These load when the work in front of the model matches them: inside a run, or when you ask for that task outside one.

| Skill | What it does |
|---|---|
| `pit-crew:adr` | Writes an architecture decision record in `docs/decisions/`, with the repo's naming convention and template. |
| `pit-crew:artifact` | Publishes the run's shareable plan page right before the 1c gate, and adds the Evidence tab after the DEV verdict. |
| `pit-crew:dev-verification` | Verifies the acceptance criteria in an ephemeral environment, a shared environment, in-cluster or in a local run, and records one case per criterion with its own evidence. |
| `pit-crew:diagram` | Draws the one visual of a phase: the architecture diagram of the plan page, the lead visual of a PR body or the optional diagram of a brainstorm page. Plain text and mermaid only. |
| `pit-crew:flow` | Creates or updates a feature flow doc in `docs/flows/`: the end-to-end narrative of a feature across services. |
| `pit-crew:jira` | Looks up an existing Jira ticket, read-only. It never creates or edits a ticket. |
| `pit-crew:linear` | Creates, searches and updates issues in a Linear workspace. |
| `pit-crew:pipeline` | The rules every phase follows: state writes, gates, the worktree rule, compact handoffs, risk-based delegation and phase results. |
| `pit-crew:pr` | Writes the title and body of a pull request in four sections: Summary, Evidence, Merge danger and Links. |
| `pit-crew:pr-comment-resolution` | Classifies, answers and resolves pull request feedback from review bots and humans, then verifies approval against the current head. |
| `pit-crew:skill-authoring` | Writing rules for the texts an agent reads: a skill, an agent, a command, a hook, a `CLAUDE.md`, an `AGENTS.md` or a rules file. |
| `pit-crew:task-routing` | Sizes the pipeline to the task by effort, time and tokens: inline or delegated, the Builder effort profile, the context budget and the rounds. |
| `pit-crew:tool-authoring` | Design rules and test templates for an MCP tool. |
| `pit-crew:triage` | Investigates a bug with evidence and reports its root cause, read-only, without fixing it. Two depths: Full and Quick. |

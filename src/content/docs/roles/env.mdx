title: env
description: The role that brings up and drives the environment where a run verifies its change.
---

The `env` role gives a run a place to verify the change. It brings the service up, sends requests, reads its state and tears it down. Phase 3 uses it for DEV verification.

## Verbs

The four required verbs are in bold. A binding without one of them shows as `partial`.

| Verb | What it is for |
|---|---|
| **`up`** | start the environment |
| **`status`** | check that it is up and healthy |
| **`request`** | send a request to the service |
| **`down`** | tear it down |

Optional: `list`, `list_pods`, `add_service`, `get_vars`, `set_vars`, `rebuild`, `restart`, `exec`, `logs`, `sync`, `deploy_history`. A step that needs one you did not bind is skipped and recorded.

Bind a destroy with `access: "orchestrator"`, so only the main session can call it.

## Adapters that ship

| Adapter | What the guide covers | Settings it reads |
|---|---|---|
| `local` | runs the service from the worktree, with Docker Compose or as a plain process. No MCP tool. Carries `up`, `status`, `request`, `exec`, `logs`, `get_vars`, `set_vars`, `rebuild`, `restart`, `list`, `down`. | `compose_file`, `service`, `health_url`, `up_command`, `project` |

How `local` behaves:

- Each run gets its own compose project, named after the run, so two runs never share containers or volumes.
- Variables go in an untracked override file. It never edits a tracked compose or env file.
- A busy port belongs to someone else. The run picks another port or reports the block. It never stops a process it did not start.
- It uses no real secret. A dependency your machine cannot run is mocked.
- Without `health_url` and no URL in the repo docs, it asks you once. It never guesses a port.

## Minimal config

In your user config:

```json
{ "roles": { "env": { "adapter": "local", "settings": { "routes": ["local"] } } } }
```

A repo may add its own settings in `.pit-crew/config.json`, and they win. The values below are placeholders:

```json
{ "roles": { "env": { "settings": { "compose_file": "compose.dev.yaml", "health_url": "http://localhost:8080/health" } } } }
```

The repo file may set only `settings` or `enabled: false` for this role. A tool id, a server or an adapter there is ignored with a warning.

## When it is off

Verification takes the local route, or none. With none, each acceptance criterion is reported as not tested.
